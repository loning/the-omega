\paragraph{Layer tags used in the main text.}
\MathTag marks theorem-level finite constructions and proofs (counts, maps, finite tables).
\InterfaceTag marks protocol-to-physics identification statements and operational dictionaries.
\MatchTag marks external comparison conventions (PDG/CODATA targets, unit/scheme choices) that never serve as premises for theorem-level claims.
\AuditTag marks explicit candidate families/objectives/tie-break rules and other audit/provenance statements (including \emph{not used in proofs} remarks).

The inference ledger (Appendix~\ref{app:inference_ledger}) records dependency status using the five tags \textsf{[Math]}, \textsf{[Prot]}, \textsf{[Iface]}, \textsf{[CAP]}, and \textsf{[Open]}.
These ledger statuses are not additional main-text layer tags; they are used only for audit and dependency tracking.

\paragraph{Wish and Motive (interface language; not used in proofs).}
\InterfaceTag We use \emph{Wish} as shorthand for a protocol-stable target datum/structure (a reproducible stable readout type and its associated invariants), and \emph{Motive} as shorthand for an auditable objective functional that combines mismatch certificates with bounded implementation cost.
\AuditTag These names are organizational and reader-facing: they do not add new axioms, and they are not used as premises in theorem-level proofs.
For a compact template definition (reader-facing; not used in proofs), see Appendix~\ref{app:wish_motive_definitions}.
The only primitives are the tick (Axiom~\ref{ax:readout_sequentiality}) and CAP (Axiom~\ref{ax:cap}); see also Figure~\ref{fig:inference_map} and Appendix~\ref{app:tick_cap_derivation}.

\AuditTag We follow the dependency legend in Figure~\ref{fig:inference_map}: theorem-level implications flow along solid arrows, while interface dictionaries and audit overlays (dashed/dotted arrows) never serve as premises for theorem-level proofs.

\section*{Reader guide (recommended paths)}
\addcontentsline{toc}{section}{Reader guide (recommended paths)}
This paper supports four complementary reading paths. The main text is organized into eight parts: Contract (Part I), Tick-first (Part II), Periodic Core (Part III), Structure (Part IV), Matter (Part V), Dynamics (Part VI), Validation (Part VII), and Recursive closure (Part VIII).
\begin{itemize}
\item \textbf{Narrative path (short mainline).}
Read the tick dictionary (Section~\ref{sec:tick_calculus}), then the folding core at $(m,n)=(6,3)$ (Section~\ref{sec:folding_core}), then the SM labeling closure (Section~\ref{sec:sm_labeling_closure}), and finally the falsifiability statements (Section~\ref{sec:falsifiability}).
If you want one minimal spine: \textit{Section~\ref{sec:tick_calculus} $\to$ Section~\ref{sec:folding_core} $\to$ Section~\ref{sec:sm_labeling_closure} $\to$ Section~\ref{subsec:p3_resolution_jumps}.}
\item \textbf{Frequency-first dynamical closure (equivalence $\to$ action $\to$ EOM $\to$ thermo).}
Read the equivalence semantics and frequency-first dictionary (Section~\ref{app:equivalence_semantics}), then the CAP closure of a minimal continuum action (Section~\ref{app:cap_continuum_action_closure}), then the variational field equations (Section~\ref{app:variational_field_equations}), and finally the thermodynamic closure (Appendix~\ref{app:thermodynamics_from_equivalence}).
For matching-layer delay/redshift templates used as operational proxies, see Appendix~\ref{app:time_mass_delay} and Appendix~\ref{app:time_mass_delay_reference}.
\item \textbf{Extended self-contained closures (overhead gravity / quantum / RG / cosmology).}
For the overhead-to-gravity closure and the $\chi$ reconstruction protocol, see Sections~\ref{app:overhead_to_gravity_closure} and \ref{app:chi_reconstruction_protocol}.
For the quantum readout interface and Born-probability rigidity, see Appendix~\ref{app:quantum_measurement_born}.
For RG/running couplings in the $r$ coordinate, see Appendix~\ref{app:running_couplings_resolution_flow}.
For cosmology as resolution flow, see Appendix~\ref{app:cosmology_resolution_flow}.
\item \textbf{Audit path (what depends on what).}
Verify the declared inputs and the dependency hierarchy using Figure~\ref{fig:inference_map} and Appendix~\ref{app:inference_ledger}, then spot-check representative rigidity certificates (e.g.\ Tables referenced in Sections~\ref{sec:couplings_cp} and \ref{sec:mass_spectrum_closure}).
\item \textbf{Reproducibility path (run the pipeline).}
Use Appendix~\ref{app:reproducibility} and run \path{python3 scripts/run_all.py} to regenerate \path{sections/generated/} and the figures.
The paper's definitions and candidate-family specifications are the logical source of truth; the scripts are the deterministic reproducer.
\end{itemize}
