\section*{A.2 Motive: Auditable objective functional (interface+CAP)}
\addcontentsline{toc}{section}{A.2 Motive: Auditable objective functional (interface+CAP)}

\InterfaceTag We use \emph{Motive} as shorthand for an auditable objective functional that combines mismatch certificates with bounded implementation cost.
Formally, given a Wish, a Motive is a functional $J$ on a finite candidate family that quantifies mismatch, cost, and stability.
The CAP axiom (Axiom~\ref{ax:cap}) then selects the unique minimizer of this functional.
\AuditTag In the unified selection vocabulary (Section~\ref{sec:unified_spine}), this is an instance of deterministic finite-family selection with an explicit objective and tie-break (Appendix~\ref{app:branching_selection_rigidity}).
\AuditTag Like Wish, this term is organizational: the only primitives are the tick (Axiom~\ref{ax:readout_sequentiality}) and CAP (Axiom~\ref{ax:cap}); see also Figure~\ref{fig:inference_map} and Appendix~\ref{app:tick_cap_derivation}.

\paragraph{Protocol state variables and what CAP actually selects.}
\InterfaceTag In this paper, CAP is used not only to pick numerical constants inside a finite ansatz class, but also to close discrete protocol-state choices that would otherwise be underdetermined at the interface level.
Concretely, the protocol state at a target scale is treated as a triple
\[
(m,n,K),
\]
where $m$ is the window length (word resolution), $n$ is the addressing order on the chosen display basis when spatial diagnostics are invoked, and $K$ is a declared readout kernel (equivalently: a declared readout weighting rule / probability assignment on the finite objects at that resolution).
\AuditTag Each component is selected only within an explicitly declared finite candidate family, by an explicit objective and deterministic tie-break, and is recorded in the tick\,+\,CAP derivation spine (Appendix~\ref{app:tick_cap_derivation}).
This convention is critical for avoiding hidden knobs: kernel choice is treated as part of the interface state, not as an implicit background assumption.
\AuditTag When an interface output depends on multiple protocol-state components simultaneously, the default closure object is the joint CAP-selected state $(m^\ast(\mu),n^\ast(\mu),K^\ast(\mu))$ at the target scale $\mu$ under an explicit finite candidate family and a joint key $J_\mu$; see Appendix~\ref{subsec:tick_cap_joint_key_contract}.
\AuditTag For reproducibility, the selected protocol states used by this paper are written as generated artifacts (\path{sections/generated/protocol_state_selected.tex} and \path{sections/generated/protocol_state_selected.json}) and are included in Appendix~\ref{app:generated_tables}.
