\section{A candidate matching module: $\alpha_{\mathrm{geo}}$ as a three-channel impedance (audit-only)}
\label{app:alpha_geo_impedance_candidate}

\paragraph{Scope and status.}
\AuditTag This appendix records an optional candidate family for organizing electromagnetic-coupling normalization as a three-channel ``impedance'' sum.
It is audit-facing only: it does not enter theorem-level folding proofs and it does not replace the paper's CAP-closed coupling dictionaries (Section~\ref{sec:couplings_cp}).
Its role is to provide a well-typed, explicitly scoped comparator module that can be activated only under an explicit registry/MDL accounting rule.

\subsection{Three-channel impedance form (candidate dictionary)}
\label{subsec:alpha_geo_impedance_form}

\InterfaceTag Consider a candidate decomposition
\[
\alpha_{\mathrm{geo}}^{-1}=V_{\mathrm{bulk}}+V_{\mathrm{boundary}}+V_{\mathrm{line}},
\]
interpreted as a sequential (series) accumulation of readout costs across three topologically distinct strata.
The key constraint is that this is a \emph{process cost} (log-additive) rather than a metric distance; it is therefore a dictionary-level statement.

\subsection{A minimal finite family and an audit gate}
\label{subsec:alpha_geo_impedance_audit_gate}

\AuditTag To avoid hidden knobs, this module may only be invoked in the following audited form:
\begin{itemize}
\item \textbf{Finite candidate family.} Declare an explicit finite family $\mathcal{F}_\alpha$ of triples $(V_{\mathrm{bulk}},V_{\mathrm{boundary}},V_{\mathrm{line}})$.
Each component must be specified either by a closed-form expression from a finite list of allowed objects (e.g.\ a short list of group-volume conventions) or by a bounded rational grid.
\item \textbf{Objective and tie-break.} If a numerical comparison is made, declare the objective (e.g.\ mismatch to CODATA at a specified matching point) and a deterministic tie-break.
\item \textbf{Registry/MDL accounting.} If multiple candidate families are compared (or if the family is enlarged), the global family registry and look-elsewhere control must be recorded (Appendix~\ref{app:global_model_selection_mdl}).
\end{itemize}

\begin{remark}[Relation to existing $\alpha$ audits in z128]\label{rem:alpha_geo_relation_to_z128_audits}
\AuditTag z128 already records bounded-family coupling normalization and mismatch audits in Section~\ref{sec:couplings_cp} and in the K4 audit family (Appendix~\ref{app:external_falsification_protocols_k4} and Appendix~\ref{app:k4_alpha_link_audit}).
The present candidate is a separate, optional comparator module: it is admissible only if its candidate-family declaration is explicit and does not conflict with the scheme/units contracts used elsewhere.
\end{remark}
