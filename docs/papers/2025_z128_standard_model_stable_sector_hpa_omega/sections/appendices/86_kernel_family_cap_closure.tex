\section{Kernel-family CAP closure: readout kernels as explicit finite choices}
\label{app:kernel_family_cap_closure}

\paragraph{Scope and status.}
\AuditTag This appendix makes explicit a cross-cutting interface choice that otherwise tends to remain implicit:
how finite readout types are weighted when one forms scalar interface quantities (effective weights, averages, variance-like summaries, and matching-layer normalizations).
It is an interface/audit module: it introduces no theorem-level premise beyond the already-defined finite objects ($X_m$, $\mathrm{Fold}_m$, refinement maps) and the CAP axiom.

\paragraph{Why this module is needed.}
\InterfaceTag Acknowledging that the protocol state is finite does not by itself fix how one aggregates finite outcomes into a single scalar.
Any such aggregation depends on a \emph{readout kernel} choice (equivalently: a weighting rule / probability assignment) on the finite objects.
To avoid hidden knobs, this paper treats kernel choice as an explicit component of the protocol state, and closes it by CAP within an explicitly declared finite family (Appendix~\ref{app:tick_cap_derivation}, Section~\ref{subsec:tick_cap_kernels}).

\subsection{Kernel families and induced weights}
\label{subsec:kernel_family_definitions}

\paragraph{Discrete kernel as a weighting rule.}
\InterfaceTag At fixed resolution $m$, the stable sector is a finite set $X_m$ and the microstate readout space is $\Omega_m=\{0,1\}^m$.
For the purposes of this appendix, a kernel choice may be represented as either:
(i) a probability distribution $\mu_m$ on $X_m$, or (ii) a weight function $K_m:X_m\to\RR_{>0}$ used to define $\mu_m$ by normalization.
We write
\[
\mu_m(w)=\frac{K_m(w)}{\sum_{v\in X_m}K_m(v)}.
\]

\paragraph{Pushforward and refinement.}
\InterfaceTag When one changes resolution, kernel-dependent outputs must be compared through the refinement maps already fixed in the finite model.
In particular, under window uplift $m'\ge 6$ one has the prefix projection $\pi_{m'\to 6}:X_{m'}\to X_6$ (Appendix~\ref{app:functorial_refinement}), and any $\mu_{m'}$ on $X_{m'}$ induces a pushforward distribution on $X_6$ by
\[
(\pi_{m'\to 6})_\#\mu_{m'}(u):=\sum_{w\in X_{m'}:\ \pi_{m'\to 6}(w)=u}\mu_{m'}(w).
\]
This is the formal meaning of ``effective fractions'' such as an $18$ vs.\ $3$ split acquiring a small correction: the set cardinalities remain integers, while the induced weights on the base types need not be uniform.

\subsection{A minimal kernel family (audit-facing)}
\label{subsec:kernel_family_minimal}

\paragraph{A finite candidate family.}
\AuditTag In the mainline audit contract, kernel choice is never left as a continuous knob.
We therefore restrict to explicit finite kernel families.
For a fixed window length $m$, the minimal audit-facing family used below consists of the following discrete candidates:
\begin{itemize}
\item \textbf{Type-uniform kernel} (\textsf{K0}): $K_m(w)\equiv 1$ for all $w\in X_m$.
\item \textbf{Microstate-pushforward kernel} (\textsf{K$\Omega$}): sample $N$ uniformly from $\{0,\dots,2^m-1\}$ and set $W=\mathrm{Fold}_m(N)$; this induces
\[
\mu_m(w)=\frac{|\mathrm{Fold}_m^{-1}(w)|}{2^m}.
\]
\item \textbf{Tempered degeneracy family} (\textsf{K}$_t$): for a fixed finite rational grid $t\in\mathcal{T}$, set $K_m(w)=g_m(w)^t$ where $g_m(w)=|\mathrm{Fold}_m^{-1}(w)|$.
\end{itemize}
\AuditTag The family is finite by construction once $\mathcal{T}$ is finite.
In the present audit example we use $\mathcal{T}=\{0,\tfrac14,\tfrac12,\tfrac34,1\}$.

\paragraph{Complexity key (tie-break).}
\AuditTag To keep the selection deterministic and audit-facing, we use a lexicographic key that prefers:
(i) smaller mismatch, then (ii) lower kernel description complexity (e.g.\ smaller denominators in $t$ and simpler family tags), and only then (iii) smaller resolution parameters if those remain free.
