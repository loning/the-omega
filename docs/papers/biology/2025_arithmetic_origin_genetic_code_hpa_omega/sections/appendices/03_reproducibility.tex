\section{Reproducibility}
\label{app:reproducibility}

This paper includes minimal, auditable scripts that reproduce the finite encoding search, codon tables, and sequence-spectrum extraction.
Appendix~\ref{app:isomorphism_dictionary} records the shared interface template in which these scripts serve as auditable instances (bounded search, stable-sector folding, and protocol-level statistics).
All scripts are standard-library Python and live under:
\begin{center}
\path{docs/papers/biology/2025_arithmetic_origin_genetic_code_hpa_omega/scripts/}
\end{center}

\subsection{What is reproduced}
The scripts reproduce:
\begin{itemize}
\item $\mathrm{Fold}_6$ computation for $N=0,\dots,63$ (via greedy Zeckendorf digits);
\item the exhaustive scan of all $24$ two-bit nucleotide encodings, including the unique identification of $\mu^\ast$;
\item stop-codon fine structure, boundary-sector codon list, and the amino-acid spectral summary;
\item mutual-information diagnostics under uniform codon prior;
\item sequence-level $(Z,U)$ traces for arbitrary DNA/RNA FASTA inputs, with optional ORF extraction.
\item genome-scale scans of the human RefSeq mRNA corpus (best-ORF selection, terminal stop statistics, stop-context windows, and $Z$-spectrum fingerprint metrics) \cite{NCBIRefSeq};
\item recoding-site extraction (Sec/Pyl) and context tests via \texttt{transl\_}\allowbreak\texttt{except};
\item nonstandard translation-table scanning from NCBI \path{gc.prt} \cite{NCBIGCPRT,NCBIGeneticCodes}.
\end{itemize}

\paragraph{What is a theorem vs.\ what is a finite enumeration.}
Classical arithmetic facts (Zeckendorf uniqueness, Fibonacci counts of admissible words) and the window-$6$ preimage characterization of $\mathrm{Fold}_6$ (Appendix~\ref{app:fold6_preimages}) are treated as mathematical results.
The scripts are provided to make the finite instances auditable and to produce tables and diagnostics without manual transcription.
The only ``search'' performed is over a finite, explicitly bounded space (the $24$ nucleotide encodings).

\subsection{Main entry points}
\begin{itemize}
\item \path{exp_genetic_code_decompiler.py}: generates all fragments in \path{sections/generated/} and prints key checks.
\item \path{fetch_datasets.py}: downloads public datasets described in \path{data/manifest.json} and updates checksums.
\item RefSeq transcriptome scan: \path{exp_refseq_transcriptome.py}.
\item RefSeq shard merge: \path{exp_refseq_transcriptome_merge.py}.
\item \path{exp_recoding_sites.py}: recoding-site extraction and summary tables (Sec/Pyl).
\item \path{exp_nonstandard_codes.py}: nonstandard translation-table scan from \path{gc.prt}.
\item \path{exp_nonstandard_sequence_tests.py}: sequence-level nonstandard-code tests driven by \path{manifest.json}.
\item \path{exp_corpus_panel.py}: cross-domain corpus panel scan driven by \path{manifest.json}.
\item \path{seq_spectrum_cli.py}: command-line sequence spectrum tool (FASTA input, frame/ORF options, TSV/JSONL outputs).
\end{itemize}

\subsection{One-command end-to-end run}
The repository includes a single driver that can refresh datasets, regenerate all LaTeX fragments, and build the PDF:
\begin{verbatim}
python3 scripts/run_all.py --download --pdf
\end{verbatim}
If your environment cannot validate the TLS certificate chain for NCBI/Ensembl endpoints, add:
\begin{verbatim}
python3 scripts/run_all.py --download --insecure --pdf
\end{verbatim}

\subsection{Regenerating LaTeX fragments only (no network)}
If the data bundles and cached JSON summaries are already present under \path{data/}, you can regenerate all LaTeX fragments without downloading anything:
\begin{verbatim}
python3 scripts/run_all.py --no-download
\end{verbatim}
This refreshes \path{sections/generated/} and updates any fragments emitted from cached summaries (e.g.\ RefSeq merge, recoding-site summaries) without forcing recomputation.

\subsection{Quick run (smoke test)}
For a fast local sanity check (small subsamples; no network), run:
\begin{verbatim}
python3 scripts/run_all.py --no-download --pdf \
  --refseq-max-shards 1 --refseq-max-records 5000 \
  --recoding-max-files 10 \
  --panel-max-records 5000 \
  --nonstandard-max-records 5000
\end{verbatim}
This is intended only to validate that scripts execute, fragments are produced, and the PDF builds; it does not reproduce the full reported statistics.

\subsection{Sanity checks for generated artefacts}
Two lightweight validators are included:
\begin{verbatim}
# Check that sections/generated/*.tex are non-empty
# (and meta sidecars are well-formed when present)
python3 scripts/validate_generated_fragments.py

# Check key JSON artefacts used for Supabase import / cross-run consistency
python3 scripts/validate_artifacts.py
\end{verbatim}

\subsection{Sequence spectrum CLI usage}
The CLI requires at least one output. Use \path{--out} (per-codon TSV trace) and/or \path{--summary-out} (per-segment JSONL summary).
The Zeckendorf window length can be set via \path{--m} (default: $m=6$).

\paragraph{Full sequence (single frame).}
\begin{verbatim}
python3 scripts/seq_spectrum_cli.py \
  --fasta your_sequence.fasta \
  --frame 0 \
  --m 6 \
  --out out_trace.tsv \
  --summary-out out_summary.jsonl \
  --stop-window 10
\end{verbatim}

\paragraph{ORF mode (single frame).}
ORFs are extracted using start \texttt{AUG} and stops \texttt{UAA/UAG/UGA} in the chosen frame.
\begin{verbatim}
python3 scripts/seq_spectrum_cli.py \
  --fasta your_sequence.fasta \
  --frame 0 \
  --m 6 \
  --orfs --min-codons 100 \
  --summary-out orf_summary.jsonl \
  --stop-window 10
\end{verbatim}

\paragraph{Summary fields (JSONL).}
Each JSON line corresponds to one segment (either \texttt{full} or one ORF) and includes:
\begin{itemize}
\item counts of codons and boundary hits;
\item $V$ and $\Delta$ histograms;
\item start/stop split counts via \texttt{start\_VDelta\_hist} and \texttt{stop\_VDelta\_hist};
\item optional stop-context uplift statistics (before/after windows) when \path{--stop-window>0}.
\end{itemize}

\subsection{Testing nonstandard genetic codes}
For translation-table level tests of prediction~P3, \path{exp_nonstandard_codes.py} parses the NCBI table file \path{data/gc.prt} and reports the stop/start sets and their boundary-hit metrics under $\mu^\ast$.
For sequence-level tests on organismal CDS corpora (e.g.\ code-specific start/stop usage and boundary-hit enrichment), \path{exp_nonstandard_sequence_tests.py} reads \path{data/manifest.json} and evaluates the example corpora listed under \path{panels/nonstandard\_examples\_v1}.
To test a specific organismal code, either:
\begin{itemize}
\item use \path{exp_nonstandard_codes.py} directly (translation-table level), or
\item run \path{exp_nonstandard_sequence_tests.py} on an organism-specific CDS FASTA dataset listed in \path{manifest.json}.
\end{itemize}
The folding map $\mathrm{Fold}_6$ and all index-level invariants remain unchanged; only the semantic labeling layer changes.

\paragraph{Refreshing the transcript FASTA files.}
If you wish to refresh these sequences from the upstream sources, the following commands fetch the corresponding entries (network required):
\begin{Verbatim}
mkdir -p data
curl -L "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=nuccore&id=NM_000518.5&rettype=fasta&retmode=text" \
  -o data/NM_000518.5.fasta
curl -L -H "Accept: text/x-fasta" "https://rest.ensembl.org/sequence/id/ENST00000381330?type=cdna" \
  -o data/ENST00000381330.5.fasta
\end{Verbatim}
\cite{NCBIRefSeq,Ensembl}
