\subsection{Scheme reparametrization invariance: an audit contract (dictionary-level)}
\label{app:scheme_invariance_audit_contract}

This appendix records a minimal audit contract for ``scheme dependence'' and ``scheme invariance'' within the paper's matching-layer semantics.
It does not attempt to construct a nonperturbative renormalization scheme; it only fixes what must remain invariant when one changes the scheme parametrization, and what is allowed to change.

\subsubsection{Contract E0: what a scheme change is (in this manuscript)}
\paragraph{Coupling reparametrization (dictionary).}
\MatchTag A scheme choice can be modeled as a local reparametrization of coupling coordinates,
\[
g \mapsto g'=\mathcal{R}(g),
\]
with $\mathcal{R}$ invertible on a declared domain.
In the $r$ coordinate, the RG flow is a vector field; under coordinate change, $\beta$ transforms by pushforward.
Therefore $\beta$-coefficients and intermediate running couplings are scheme-dependent objects.

\paragraph{Shift semantics in $r$.}
\MathTag Appendix~\ref{app:running_couplings_resolution_flow} records that a multiplicative rescaling of a transmutation scale (or an equivalent finite matching factor) induces an additive shift in the resolution coordinate $r$ (Lemma~\ref{lem:lambda_rescaling_shift_r}).
This makes scheme changes auditable: they become explicit shifts and/or explicit reparametrizations, not hidden knobs.

\subsubsection{Contract E1: invariants and allowed non-invariants}
\paragraph{Invariants.}
\AuditTag The audit contract requires that the following be treated as invariants under a declared scheme reparametrization:
\begin{itemize}
\item (E1-I1) dimensionless physical observables (cross sections, decay ratios, properly defined phase/delay observables) within their declared measurement dictionary;
\item (E1-I2) qualitative features that are coordinate-free within a bounded audit (e.g.\ sign patterns that are protected by a monotone coordinate change when the Jacobian is positive);
\item (E1-I3) ordering statements that are explicitly phrased in scheme-invariant terms (e.g.\ monotonicity in a physical scale variable rather than in a scheme-dependent parameter).
\end{itemize}

\paragraph{Allowed non-invariants.}
\AuditTag The contract allows the following to vary with scheme:
\begin{itemize}
\item (E1-N1) the numerical values of couplings at an intermediate scale, including $\alpha_i(\mu)$ at non-anchor points;
\item (E1-N2) the apparent ``unification scale'' inferred by intersecting scheme-dependent running couplings, unless a scheme-fixing normalization is supplied (Appendix~\ref{app:u3_normalization_embedding_registry});
\item (E1-N3) any object that depends on a truncation order (one-loop vs two-loop) unless an error budget is included (Appendix~\ref{app:coupling_unification_audit_in_r}).
\end{itemize}

\subsubsection{Contract E2: a minimal checklist for future audits}
\AuditTag Any module that introduces scheme-dependent running must provide:
\begin{itemize}
\item a bounded scheme family (registry) and a deterministic tie-break rule;
\item an explicit statement of which outputs are invariants and which are scheme-dependent;
\item at least one internal consistency check that does not collapse into the tuning target.
\end{itemize}
