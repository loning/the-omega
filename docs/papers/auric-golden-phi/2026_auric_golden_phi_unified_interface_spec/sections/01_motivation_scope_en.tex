\section{Motivation and Scope}

\subsection{Why a ``Master Thesis / Interface Specification''}

The individual papers in this directory have each formed self-contained ``definition--theorem--reproducible protocol'' chains, yet they heavily reuse the same set of structural modules:
\begin{itemize}
  \item \textbf{Dynamical systems module:} translation on compact abelian groups / tori and induced maps, or their geometrically equivalent hyperspace cut-and-project sections;
  \item \textbf{Readout module:} binary sequences and transition kernels induced by finite-resolution windows / binary partitions;
  \item \textbf{Symbols and stabilization module:} Sturmian minimal complexity, golden-mean legal languages, and Zeckendorf canonical form;
  \item \textbf{Fiber and time module:} stabilization kernel preimage fibers, cylindric set posterior measure contraction, and entropy rate;
  \item \textbf{Protocol / arithmetic interface module:} difference certificates, Hecke skeletons, $\zeta$ interface, and other auditable ports.
\end{itemize}

Therefore, the most reasonable integration approach is: preserve the main proof chains of individual papers while adding an ``interface specification'' as a master gateway, such that each paper can be expressed as an instance (or extension) of the same interface, and its additional assumptions are explicitly classified as: geometric realization assumptions / readout assumptions / stabilization rules / statistical assumptions / arithmetic interface assumptions.

\subsection{Input Minimization in This Master Thesis}

This master thesis fixes only the minimal inputs:
\begin{itemize}
  \item Measure-preserving dynamical system $(X,\mathcal{B},\mu,T)$ (or compact group translation / factor system);
  \item Finite alphabet readout and finite window length $m$;
  \item Computability of the stabilization kernel $\Fold_m$ and uniqueness of canonical form (Zeckendorf logic);
  \item Invocation conditions for SMB/KS (ergodicity, generating partition, or equivalent assumptions).
\end{itemize}
All remaining structures appear as ``optional extension ports.''
