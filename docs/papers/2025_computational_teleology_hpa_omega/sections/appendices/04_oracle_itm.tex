\section{Oracle language and interactive observers}
\label{app:oracle_itm}

This appendix clarifies the formal position of the oracle/interaction vocabulary used in Section~\ref{subsec:observer_oracle}.

\subsection{Oracle (relative computability)}
An oracle machine (o-machine) extends a Turing machine with access to an external predicate that can be queried but not computed internally \cite{Turing1939}.
In modern complexity language, this is the basis of relativization and oracle complexity classes.

In this paper, ``oracle-like'' is used as a resource-language label: when a readout/selection step conditions on a predicate that is undecidable from within the model, one may consistently describe the conditioning as supplying an external resource.

\subsection{Interaction (process vs function)}
Observation is modeled as an ongoing process rather than a one-shot input--output function.
This motivates using interactive computation language, where the environment is a stream and the observer is an online machine.
The analogy to interactive proof systems is especially useful as a resource metaphor: interaction can raise verification power, culminating in the theorem $\mathrm{IP}=\mathrm{PSPACE}$ \cite{Shamir1992}.

\subsection{What is not claimed}
Nothing in this paper claims that physical reality literally contains oracle hardware.
The oracle/interaction vocabulary is explicitly placed in the interpretation/interface layer, as a way to talk about conditionalization and resource accounting while keeping theorem-level statements (unitarity, locality, undecidability) logically separate.
